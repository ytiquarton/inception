# User Documentation

This guide explains how to use the Inception WordPress site and check that its
services are available.

## Services provided

The project starts three services:

- **Nginx** accepts secure website connections on HTTPS port `443`.
- **WordPress** serves the website and its administration panel.
- **MariaDB** stores the WordPress database.

The database is not published directly to the host. It is reachable by the other
services over the project's private Docker network.

## Start and stop the project

An administrator starts the project from the repository directory:

```bash
make
```

To stop the containers without deleting the website or database data:

```bash
make down
```

Starting it again with `make` reuses the saved data. Do not use `make fclean`
unless you intend to permanently delete the local site and database.

## Visit the website and administration panel

Open the address configured by `DOMAIN_NAME` in `srcs/.env`. The example
configuration uses:

- Website: `https://mclaudet.42.fr`
- WordPress administration: `https://mclaudet.42.fr/wp-admin`

If the domain does not resolve on a local machine, an administrator can add it
to that machine's `/etc/hosts` file, mapping it to the server's IP address.

The site uses a self-signed TLS certificate generated by Nginx. Browsers will
show a certificate warning; this is expected for the default local setup.

## Credentials

The WordPress administrator username created at first installation is `boss`.
Its initial password is read from:

```text
secrets/credentials.txt
```

The database credentials are stored in the following files:

- `secrets/db_password.txt`: password for the WordPress database user
- `secrets/db_root_password.txt`: MariaDB root password

These are deployment credentials, not website login names. Keep the files
private, restrict access to them, and do not share their contents in chat, logs,
or screenshots. The WordPress administrator can change the website password
from the WordPress dashboard. Changing `credentials.txt` after WordPress has
already been installed does not change the existing WordPress account password.

The setup script also creates a subscriber account named `simple_user`; its
initial password is set in the setup script. An administrator should change or
remove that account before using the site beyond a local demonstration.

## Check that the services are running

From the project directory, check container status:

```bash
docker compose -f srcs/docker-compose.yml ps
```

The `nginx`, `wordpress`, and `mariadb` containers should be listed as running.
To view startup or runtime messages:

```bash
docker compose -f srcs/docker-compose.yml logs
```

To inspect one service:

```bash
docker compose -f srcs/docker-compose.yml logs nginx
docker compose -f srcs/docker-compose.yml logs wordpress
docker compose -f srcs/docker-compose.yml logs mariadb
```

If the website is unavailable, confirm that Docker is running, the containers
are up, port `443` is available, and the configured domain resolves to the
server. Ask the administrator to check the logs if the issue persists.
